Have a Chrome extension you want to use in Safari on your own Mac or iPhone? `extport port safari` downloads the extension straight from the Chrome Web Store (or reads a local `.crx`, `.zip`, or folder), converts it to a Safari Web Extension, signs it with a certificate already in your Mac's Keychain, and installs it directly onto your device — in one command, with **no extport login and no App Store Connect setup**.

## Quick start

Requires **macOS** with **Xcode** installed from the [Mac App Store](https://apps.apple.com/app/xcode/id497799835) (open Xcode once after installing to finish setup — signing in with a free Apple Account under **Xcode → Settings → Apple Accounts** lets Safari trust your extensions without enabling unsigned extensions).

<Tabs>
  <TabItem label="macOS Installer (Recommended)">

After a macOS install, the host app opens automatically with a setup guide — turn the extension on under **Safari → Settings → Extensions**. On iOS, enable it under **Settings → Apps → Safari → Extensions**.

## Supported inputs

Pass any of the following as `<source>`:

- **Chrome Web Store URL** (`chromewebstore.google.com/detail/...` or legacy `chrome.google.com/webstore/detail/...`)
- **32-character CWS extension ID** (e.g. `icpgjfneehieebagbmdbhnlpiopdcmna`)
- **Local `.crx`, `.zip`, or unpacked extension folder**

Everything runs **100% locally on your Mac** — nothing is uploaded to extport's servers.

:::note[Manifest V3 only]
Only Manifest V3 extensions are supported. If an extension declares Chrome-only APIs that Safari does not implement (such as `chrome.identity`, `chrome.offscreen`, or `chrome.sidePanel`), the CLI prints a warning up front and continues converting so you know what to expect.
:::

## Signing — zero certificate ceremony

Just like Xcode, `extport port safari` scans your Mac's ambient Keychain automatically:

- **One matching certificate** (`Apple Development` or `Developer ID Application`) → selected automatically, with the real Apple Developer Team ID extracted from the certificate's `OU` field.
- **Multiple certificates** → prompts you interactively to pick one (or pass `--sign <name|sha1>` to skip the prompt).
- **No certificate / `--no-sign`** → falls back to ad-hoc signing on macOS (requires enabling unsigned extensions in Safari after each restart). On iOS, `--no-sign --output ./out` exports an unsigned `.ipa` for sideloading.

### Recommended: one-time free Apple Account setup

You don't need a paid $99/year Apple Developer membership to avoid Safari's unsigned-extension prompts. Signing in to Xcode once with a **free Apple Account** creates a local `Apple Development` certificate (valid for **1 year**, with **no 7-day expiry on macOS**). Once created, `extport port safari` signs automatically — Safari trusts the extension permanently even with **Show features for web developers** turned off, and you never need to open Xcode again.

1. Open **Xcode → Settings → Apple Accounts** and click **Sign In…** with any free Apple Account.

   ![Xcode Apple Accounts settings showing the Sign In button](../../assets/screenshots/port-safari-xcode-sign-in.jpg)

2. Click into your **Personal Team** and select **Manage Certificates…**.

   ![Xcode Personal Team settings showing the Manage Certificates button](../../assets/screenshots/port-safari-xcode-personal-team.jpg)

3. Click **`+`** in the bottom-left corner and choose **Apple Development** to mint your local certificate, then click **Done** and close Xcode.

   ![Xcode Signing certificates dialog showing a newly created Apple Development certificate and the bottom-left plus button](../../assets/screenshots/port-safari-xcode-certificates.jpg)

:::note[iOS free-account limits]
On **macOS**, a free Personal Team build has no embedded provisioning profile, no 7-day expiration, and needs no Safari Developer toggle. On **iOS**, Apple limits free accounts to 7-day installs and 3 active App IDs per 7 days (each Safari extension uses 2: host app + `.appex`).
:::

<details>
<summary>Skipping Xcode sign-in? How to enable unsigned (ad-hoc) extensions in Safari</summary>

If you run `extport port safari` without any certificate in Keychain (or with `--no-sign`), the macOS app is ad-hoc signed. To enable it in Safari:

1. Open **Safari → Settings → Advanced** and check **Show features for web developers**.

   ![Safari Advanced settings with Show features for web developers checked](../../assets/screenshots/port-safari-advanced.jpg)

2. Open **Safari → Settings → Developer** and check **Allow unsigned extensions**. Safari resets this checkbox whenever you quit and reopen the browser.

   ![Safari Developer settings with Allow unsigned extensions checked](../../assets/screenshots/port-safari-developer.jpg)

3. Open **Safari → Settings → Extensions** and check the box next to your extension.

</details>

## In-place updates

By default, bundle identifiers are derived deterministically (`dev.extport.<team|local>.<extension-id>`). Re-running `extport port safari <url>` when the upstream extension ships a new version installs over the existing app while keeping your Safari extension permissions and `browser.storage` data intact.

## Common flags

| Flag                      | Description                                                           |
| ------------------------- | --------------------------------------------------------------------- |
| `--platform <macos\|ios>` | Target platform (default: `macos`)                                    |
| `--output <path>`         | Export the built `.app` (macOS) or `.ipa` (iOS) instead of installing |
| `--sign <name\|sha1>`     | Pick a specific Keychain signing identity non-interactively           |
| `--no-sign`               | Skip Keychain lookup (ad-hoc on macOS; requires `--output` on iOS)    |
| `--device <name\|udid>`   | Target a specific physical iOS device (`--platform ios` only)         |
| `--bundle-id <id>`        | Override the deterministic bundle identifier                          |
| `--keep-project <dir>`    | Keep a copy of the generated self-contained `.xcodeproj`              |
| `--debug`                 | Stream raw converter, `xcodebuild`, and `devicectl` output            |

## Publishing to the App Store instead?

`extport port safari` is for local personal installation on your own devices. When you're ready to ship your own extension to the Mac App Store and iOS App Store, see the [Safari publishing guide](/stores/safari/) (`extport safari-build`).
